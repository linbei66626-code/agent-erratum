2. **改了 staged helper 后必须重建叠加 checkout 与 manifest**：

   （会重建 multicall+叠加两棵树并刷新 `manifest.json` / `stack-manifest.json` 摘要；
   RUN 授权门的**规则**不变，只是 pin 的字节跟着新 helper 走）。
3. **交付 staging 有专用工具**：`tools/stage_*_delivery.py` 生成 `before/after/diffs/before-after.json`，
   `tools/write_sha256sums.py <dir>` 写/校验 `SHA256SUMS`；before 优先取上一轮交付的 after 副本，
   取不到时按"反向应用本轮编辑"重建并在 `baseline` 字段标注 `reconstructed`。
4. **不要用 `rm` 清理别的交付目录**：本会话曾误删 r1 交付的一个证据文件，靠"用交付内的旧工具脚本
   + 记录参数重算"才按原 SHA 复原；任何删除前先确认目录归属。
5. **长套件后台跑**：`tests/test_ae_cloud_re_multiturn.py` + `tests/test_ae_no_compaction.py` ≈ 14 min；
   `tests/test_ae_no_compaction.py` 单独 ≈ 2.5 min；前台默认超时会被杀。
6. **冻结捕获的来源摘要**：`tests/test_ae_aux_wire.py` 的 r4 夹具会把冻结摘要注入
   `ae_cloud_proxy.hashlib`（映射按当前字节现算，所以再改 proxy 也自适应）；如果改的是
   `ae_model_proxy.py` / `ae_http.py`，同样机制覆盖。
7. **新增 transport profile 时**：把该 profile 明确需要的字段加进 `TransportProfile.extra_request_fields`
   （字段白名单是精确集合；screening 就因为 `parallel_tool_calls` 被拒过一次），并把模型集合/单模型
   两种语义分清（`wire_models` vs `wire_model`）。`profile_of()` 同时接受 `CloudConfig`（`profile`）
   与 run config（`transport_profile`）。
8. **本会话工具无法访问 `openrouter.ai`**（域名解析到非公网 IP，`web_fetch` 拒绝）；厂商文档/Slug/
