# DeepSeek 任务：单 t4 接口澄清最小对照

## 目标与范围

仅实现一个显式 opt-in 的 `t4-interface-clarified-v1` 对照，检查时间信息与工具说明不完整是否影响执行。原始默认路径保持不变。本轮只做离线实现与定向验证，完成即交付停止；不联网、不 SSH、不部署、不读真实密钥、不调用模型。不要扩成新框架。

先读 `results/ae-t4-contract-diagnosis-r1/README.md` 与 `replay.json`。已观察：DeepSeek 正确选择商品并付款，但省略 attributes 导致订单规格空串；模型仅见日期，而后台用14:30检查配送时间。

## 仅两项干预

1. **完整环境时间**：沿用真实 native 环境用于检查 dispatch_time 的同一个时钟，向 Agent 提供完整当前时间。先核其初始化和来源，不取 Mac/服务器墙钟，不硬编码14:30，不从私有评分中取值。记录来源与实际值。这个信息是本对照新增的公开环境信息，不声称旧输入已具备。若无法取得一致时钟，明确报错，不猜测。用户模拟器若已有当前时间字段，与同一时钟保持一致；不要改用户人格、任务或其他提示。
2. **明确属性参数语义**：仅在发送给模型的 create_delivery_order 的 attributes 参数说明追加通用说明：“商品目录中的规格不会自动写入订单；若用户有规格要求，必须显式传入 attributes，按 product_ids 的顺序逐项对应，取值依据实际商品查询回包；省略时订单规格为空。”不将参数改成 required，不改工具执行默认值，不替模型自动补参；不写目标商品、商家或正确糖度答案。深拷贝 schema，避免污染默认路径或下一次运行。

## 实现位置与不变项

优先小改 `scripts/ae_01_cloud_t4_probe.py` 及必要的 `scripts/ae_01_local_t4_probe.py` 共享构造接口；增加显式 CLI 开关或同等简洁选择。仅必要时调整 t4_flow.py 的透传，不重构循环。不复制用户模拟器、工具或诊断器。

模型、非思考模式、温度、预算、超时、重试策略、19个工具及执行、原任务指令、偏好、工具回包上限、评分和付款停止规则全部不变。不修改 ae_capability.py、Vita 源码、旧配置与任何封存交付/现场 raw。旧默认路径不加新提醒。

记录 case_variant、两项干预的内容/时间来源；保存无密钥的实际首请求 messages/tools/model/mode，保证可与原始请求核对。与“原始输入相同”“未使用后验提醒”之类旧标记有冲突时如实更新本变体，不继承误导标签。明确是两因素同时澄清、后验探索对照，不是原生 benchmark 或 R/E，不声称能单独归因某一因素。

## 最小验收

只跑直接相关定向测试，不跑全仓、不重验几十份旧交付：

- 默认路径首请求保持原样；对照首请求只有声明的时间/说明变化（及必要身份记录），模型工具数仍19；schema required、执行绑定不变。两变体连续构造不相互污染。
- 使用真实 native 时钟证明提示时间与工具校验时间一致，换一个测试时刻仍一致，排除硬编码。
- 捕获真实云入口发出的请求，证明开关传到实际 messages/tools，不仅修改 plan；仍走现有传输/预算。
- 真实工具保留原行为：省略 attributes 仍为空且原严格诊断不通过；显式正确规格的正常 create→pay 仍可通过。不要用脚本化响应的通过宣称模型能力通过。
