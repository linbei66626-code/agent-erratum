## 影响解释的主要发现

### 1. 用户模拟器在用户消息中续写助手和支付成功

R t8/t11、E t5/t7/t10的新订单处于unpaid，均未发生真实付款，却在用户回复中出现确认、模拟支付成功和停止标记。原生用户模拟器以消息中包含STOP标记判停，导致流程结束。这些文本不是工具付款证据。

最明确实例：R t11 transcript[9]创建订单`OT3377474bc4`，最终仍unpaid；transcript[11]用户消息声称订单`TK20240613001`支付成功，并含`###STOP###`。两订单号不同。该阶段reward仍为1，因为三条rubric检查商品、规格、工作地址，没有付款条目；这不是计算错分，而是成绩与“完整购买支付”目标之间的覆盖缺口。

因此不能把18阶段结束理解为18阶段真实业务完成，也不能把所有未完成归咎于Agent记忆。此问题不改变原始成绩，本报告不另造一套主指标。

### 2. 至少存在一处工具事实与距离标准冲突

E t8 transcript[4]原生商家回包给出型动健身空间坐标103.7145,36.1055；transcript[7]距离调用使用该坐标和家庭坐标103.7195,36.1005，transcript[11]返回715.0米。评分标准却把该店列作约2.1公里、超过2公里，评委按标准判错。不能用这一条错误证明模型违反了可见距离事实。

该阶段另有购买团课次卡而非要求产品的问题，所以仅纠正距离也不会把原始总reward从0翻成1。

### 3. 相同商品的标准适用不一致

t5两臂最终都选全身油压100分钟。R的“全身SPA且时长充足”条目判false；E对应条目以100分钟基本足够判true。E此前多次试图买全身SPA却传入背部SPA的P00118，该商品信息在真实搜索回包中可见。这是商品与ID选择问题，不能直接判为偏好没有被记住。

t9 R已选大份且付款，距离项因不能确定最近而判false；E距离项依地址描述通过。R的失败不能直接改述为已证实选到过远商家。评分计算可重现与判断尺度一致是两回事。

### 4. “知道新偏好但选择不符合”与“旧偏好覆盖新偏好”不同

t7两臂都明确提到2小时，却推荐更长套餐；t9两臂都采用大份，E因可选规格改推超大份并得到用户同意。这些轨迹没有显示退回旧的小份偏好。

t10最值得保留为后续机制线索：R同时提到SPA、KTV、瑜伽后选SPA，E选KTV。但R并没有忘记KTV，且用户分别接受了不同推荐。现有一次轨迹无法区分偏好优先级解释、推荐随机差异、用户交互与记忆表示的作用。
